How to make an ebook — the full guide

From a PDF book to a clean ebook — the full method in 7 parts. On the Maker the steps are numbered 1–4; Part 7 below is the Maker's final step.

  1. 1 — Before you start: check Our Boighar, and the two purposes
  2. 2 — Get the .txt (Maker OCR, vFlat, or a .txt you already have)
  3. 3 — Proofread the .txt (by hand, or automatically)
  4. 4 — The formatted document: what “book-like” means
  5. 5 — Cover and credit
  6. 6 — Review in Google Docs / Word (optional, for an exactly-like-print look)
  7. 7 — Final formats: EPUB, PDF, AZW3, MOBI, KFX

Part 1 — Before you start

First, check whether the book is already on Our Boighar — if it is, there is no need to make it again. (If you still want your own copy, you can make it anyway.)

An ebook is made for 2 purposes:

  1. For yourself only — you may convert any PDF book, old or new, no problem. Just do not share the finished ebook online if the book is less than 10 years old.
  2. For everyone, to share with everyone — you may share it only when the book is 10+ years old, OR the writer or publisher has published the PDF publicly themselves or has no problem with it being shared online.

When you have an ebook that may be shared, send it to the Our Boighar community (Facebook group / Telegram linked on the site's About page) so it can be checked and added to the library.

Part 2 — Get the .txt

Everything after this part works from plain text. There are three ways to get it — pick one.

A) With this Maker (easiest)

  1. On the Maker, upload the PDF, write the book title and author. The line under the file picker shows a ✓ with the chosen file's name and size — if it does not, pick the file again.
  2. Tap “Test first 5 pages” first — read the preview. If the text looks clean, tap “Read the full book”.
  3. Long run? Tap the round sun button beside the screen-on description — the screen will not sleep while this tab stays open. It does not work once you switch to another app; that is the phone's rule and cannot be overridden.
  4. If you switch apps and the scan pauses, come back and tap the ▶️ Resume button in Step 2 — it is always visible, and it is enabled whenever saved progress exists for that file. Progress is saved after every page, so nothing is lost. The status also shows how long each page takes and how much time is left.
  5. When the full book finishes, Step 3 opens. Download the raw .txt from there if you are proofreading by hand.

B) With the vFlat app (if Maker OCR feels too slow)

On the Maker, Step 2 has a “PDF → .txt with vFlat (pop-up)” button with these steps:

  1. Download vFlat from this link and install it.
  2. Load the PDF in vFlat.
  3. Run OCR.
  4. Export as .txt.
  5. Come back to the Maker and put that .txt in Step 2's “Upload a .txt file” box — Step 2 is skipped.

C) You already have an OCR .txt file

Skip Step 2 entirely: upload the .txt in Step 3's box and proofreading starts right there.

Part 3 — Proofreading

This step's whole job: turn the raw .txt into proofread text, and from it a book-like document. On the Maker, tap the Manual or Automatic button and that panel opens below it — tap again to close it. Pick one.

A) By hand — Google AI Studio (Gemini)

  1. aistudio.google.com — open it.
  2. Tap the + sign and add the text file.
  3. Tap the system-instruction spot (the red-circled icon in the guide's original pictures) and paste the full proofreading prompt below.
  4. Write continue in the prompt, then Run (Ctrl + Enter).
  5. When a response finishes, write continue and Run again. Keep going until the whole book is done.
  6. On any response, tap the three dots and choose Copy as Markdown. The left dots let you move between responses.
  7. Join the copied parts into one proofread file, then upload it in the Maker's Step 3 manual panel — Step 4 opens at once. (The old route still works too: paste the Markdown into a Markdown-to-Google-Docs converter, copy into Google Docs, and export .docx — see Part 6.)

For phone

Wherever you paste, press and hold, then tap Paste when the option appears. Do not paste from the keyboard's popup — the formatting will be lost.

B) By hand — with Muse (no API key needed)

  1. Download the .txt from the Maker's Step 3.
  2. Upload it in a Muse chat and paste the Muse instruction below in the same message.
  3. When Muse finishes a chunk, write “continue” — repeat until the book is done.
  4. Join the finished chunks into one file and upload it in the Maker's Step 3 manual panel.

C) Automatically — in the Maker, with your own key

In Step 3's automatic panel: pick Google Gemini (free, easiest for most people) or OpenRouter, paste your key, tap “Check key & show free models” to see the free models on that key, pick one, and press “Proofread automatically”. The text is sent in chunks (about 8,000 characters) with the same proofreading prompt, and the answers are joined. If a free key hits its daily limit, the tool waits and retries on its own, and progress is saved after every chunk — run again to continue from the same place. The key stays only in your browser and goes directly to Google or OpenRouter — never to any server of ours. No key yet? The “No key yet — how do I get one?” button walks through it tap by tap (Gemini keys are free and need no card; they start with “AIza” — never screenshot one).

NB

  • You can attach the PDF directly in AI Studio too — but the sharing-rights note must be somewhere in the book.
  • A .docx file cannot be added directly to AI Studio.
  • Open several tabs and several books can be proofread in parallel — it takes less time overall.
  • If anything is unclear, ask in the group.

Part 4 — The formatted document

Whether proofreading was manual or automatic, the output is a document that looks like a book — not plain text. The Maker builds it with these rules, and the proofreading prompt enforces the same rules when you proofread by hand:

  • Title page — book title (and author) centred on its own page, then the book itself.
  • Chapters on new pages — every chapter heading starts a new page, headings centred.
  • Body text justified — except Arabic text, which is right-aligned.
  • Structure — # for the book title only, ## for chapters, ### for sub-sections, *** for scene breaks, page break at the end of a chapter where needed.
  • Cleanup — page numbers, running headers and footers removed; broken line breaks joined into proper paragraphs; common OCR errors fixed without changing the author's wording or modernizing old spellings.
  • Typography — -- becomes an em-dash (—), spaced hyphens become en-dashes (–) where appropriate, quotation marks standardized, *italics* for emphasis, book titles and foreign words.
  • Special text — blockquotes with >, poetry kept in stanzas with soft line breaks, footnotes kept next to their number in superscript within third brackets, endnotes and citations the same way.
  • Bangla — OCR spelling corrected (য় misread as য, and similar), titles and headings centred.
  • Arabic — errors corrected, harkat added, no brackets in Arabic text; Quranic ayahs in the form آيه ۝١٩١.
  • Navigation — a table of contents becomes a digital linked list (no printed page numbers), and a back-of-book index becomes a linked index the same way.
  • Credit page — an “About this ebook” page at the end, naming the ebook creator (your name from Step 1, if given), Our Ebook Maker and Our Boighar.

Exactly-like-print decoration (drop caps, ornaments, special fonts) cannot be produced automatically — for that, see Part 6.

Part 5 — Cover and credit

  • In Step 1, upload a cover image if you have one — the uploaded cover is the one that goes into the final ebook.
  • No cover? Use “Find a cover online” (Open Library search), or “Make a text cover”. If you don't like a style, tap “Generate another style” — there is no limit, every tap makes a new design.
  • Download the cover you like, then upload it in the upload box above — only the uploaded file goes into the ebook.
  • Put your name in Step 1's “Your name” field if you want it on the credit page (Part 4).

Part 6 — Review in Google Docs / Word (optional)

Only needed if you want the book to look exactly like the printed book, or if you took the old manual route:

  • Download the .docx from Step 4 and open it in Google Docs or Word.
  • Set the font to Noto Serif Bengali / SulaimanLipi — it looks like the original book.
  • For a full-page cover: tap the image, open Image options, uncheck lock aspect ratio under Size & rotation, set position to “Fix position on page”, then expand the image to fill the page.
  • Make any final hand formatting here (drop caps, ornaments, special fonts), then export as .docx — and if you changed it, upload that .docx in Step 5: it skips straight to the final ebook formats.

Part 7 — Final formats

Skip straight here: if you already have a formatted document (.docx) — from Part 6, or from anywhere else — upload it in the Maker's Step 5 and every earlier step is skipped. The document is read (headings kept as chapters) and all formats below become available.

Which format, for which work?

  • EPUB — phones, tablets and almost every reading app (Apple Books, Google Play Books, Moon+ Reader, the Our Boighar reader). Built automatically on the Maker.
  • PDF — layout stays exactly fixed; for printing or sharing, and for readers with no ebook app. Built on the Maker as a print-ready page — in the print dialog choose “Save as PDF”, so Bengali/Arabic shaping stays correct.
  • AZW3 — Amazon Kindle devices and apps. MOBI — older Kindles. KFX — the newest Kindle format, with enhanced typesetting.

1) Automatic — on the Maker itself

The document (.docx) is built in Step 4, and EPUB and PDF are built in Step 5, right here in your browser — nothing has to be uploaded to any site.

2) Manual — with the online-convert website (for AZW3 / MOBI)

AZW3 / MOBI cannot be built directly in a browser — they are Amazon's own formats, and this site has no server, so a server-based conversion like online-convert's cannot run automatically here. This is the manual way:

  1. Download the .docx in Step 4, or the EPUB in Step 5, automatically.
  2. Open ebook.online-convert.com, upload the file, and pick AZW3 (Kindle) or MOBI (older Kindle) as the output.
  3. Press Convert, then download the finished file.

3) With Calibre on a computer (AZW3 / MOBI / KFX)

  1. Download the EPUB in Step 5.
  2. Install the free Calibre software on a computer.
  3. Add the EPUB to Calibre → select the book → “Convert books” → pick AZW3 or MOBI as output format → OK.
  4. For KFX, add the “KFX Output” plugin to Calibre (Preferences → Plugins).

Tip: to send straight to a Kindle, EPUB itself can be sent with Send to Kindle — no conversion needed.
